# 地图与电脑设计

更新：2026-09-10。v1.4 地图配置为塔射／升级／整编的原型基线，未经试玩。保留六图 42 个节点 ID，调整营地类型和教学职责。基础属性/时空/胜负见[主文档](01-产品与玩法设计.md)，奖励见[D](03-策略与军衔设计.md)，未来体验检验见[F](07-平衡与测试计划.md)。

## A1. 布局约束

战场 360×540，左上原点。中心 X40 至 320、Y55 至 485，两城中心至少 64 逻辑单位。逻辑路径半径 18，实际触控不少于 44 屏幕逻辑像素；画面缩放不改变距离。

P=玩家，E=教学电脑，E1/E2/E3=四方互为敌人的电脑，N=中立。初始生产额度 0、效果空。地图初始等级为 1／2，局内可升至 3；首发类型为 barracks／archery／relay／fort，对应步兵营／弓营／骑营／塔营。生产与箭塔初始节拍按主文档初始化，不能用旧类型参数。所有参赛阵营至少一城，初始驻军不超基础容量，ID 全局唯一。

任何城都能直达其他城，无相邻／通道限制，无不可见地形碰撞；塔营真实射程内存在区域射击，不因可直达就保证安全。中立塔不射击；有主塔射程不得覆盖敌方出生营，至少存在一条避开塔射的扩张选择，几何与真人理解分别验证。对称地图只证明布局对称，不证明试玩公平。正式玩家固定左下，电脑旗帜位置固定以利识别；测试时轮换出生位，不把测试选项暴露为计奖功能。

正式图不要求获胜才解锁，以免卡在初学阶段；同时前两局都用 A01，不马上倾倒三套资源布局。地图没有不同奖励倍数。练兵重试恢复固定初始配置，不随机暗降难度。

首次教学：

1. 游戏时间停在 0，生产、行军、电脑全部冻结；只播放 UI 手势，读多久都不让敌人变强。
2. 提示“拖到这里，派出一半兵力”，只接受 P1 → N1；其他拖动不扣兵，提示返回目标，不弹长说明。
3. 有效松手按初始 24 兵派 12 留 12，创建兵团后启动游戏时钟；电脑第一次决策在启动后第 8 秒。
4. 首次成功占领 N1 时短提示“占领后会自动产兵”，不再暂停。
5. 首次指定拖拽完成并记录后，后续操作和重试不再限制目标；重试仍使用原始配置与 8 秒电脑初动延迟。

局部算例：P1 → N1 的路长约 125.01，延迟 1563 ms；中立守军不生产，12 对 6 后留下玩家 6。这不是整关可通关证明。

验证至少包括：占中立再扩张、过早攻击的后果、失败重试、停留教学 30 秒不改变初始局势。

## A6. 电脑参数

首轮固定规则，不使用自学习、隐藏随机、动态加兵或未来操作预测。

| 参数 | L01 | L02 | L03 |
| --- | ---: | ---: | ---: |
| 首次决策延迟（游戏秒） | 8.0 | 4.0 | 3.0 |
| 后续决策间隔（游戏秒） | 2.5 | 2.0 | 1.5 |
| 普通进攻最低出发驻军 | 16 | 14 | 12 |
| 进攻安全余量（兵） | 4 | 3 | 2 |
| 防守威胁观察窗口（秒） | 4.0 | 4.0 | 4.0 |
| 每次决策最多派兵次数 | 1 | 1 | 1 |

表中只改变决策节奏与偏好，不隐形改变属性。每次决策最多一个总动作，派兵、用卡、升级互斥。本节中产速/容量/行军时间均读取已经公开生效的主被动修正，基础教学没有修正；实际结算始终调用共同规则。

### A6.1 可见信息与合法来源

电脑可读当前公开据点属性、兵力和已出发兵团的目标/到达时间；这些信息须由数字、行军和交互查询向玩家表达。不能读取尚未松手的目标或未来输入。

- 按 ID 升序枚举己方据点，以同一派兵函数计算 S。
- 派出后至少保留 max(4, ceil(容量 × 0.10)) 兵；这是电脑偏好，不限制玩家。
- 普通攻击还需达到表中最低驻军。紧急增援可跳过最低驻军，但不能跳过保留要求。
- 若来源自己在观察窗口内有预计扛不住的攻击，则不从它出兵。
- 一次决策只选一个动作，执行后等下一时刻重新观察。

### A6.2 优先级一：增援受威胁据点

对每个己方城找到 4 秒内最早的敌军到达时间 T：

- 估计守军 = min(容量, 当前驻军 + floor(产速 × T 秒) + T 前及同刻已知友军增援)。
- T 前及同刻敌军总量不小于估计守军则视为危险；同量也要防守，不等于规则上已失守。
- 优先最后据点，再优先更早受袭者，同值按目标 ID。
- 从能在 T 前或同刻抵达、满足保留条件的己方来源增援，优先更短行军时间，再优先更多 S，再按来源 ID。
- 没有及时援军就进入下一优先级，不能传送、延迟敌军或免费补兵。

预测是公开信息启发式，不是结果保证。v1.4 对候选路线／受威胁城还需在复制状态中推进已知生产、到达与塔射到观察时刻，不生成未知玩家／电脑未来指令；塔下驻军损失、在途队剩余人数与转换必须考虑。真实事件仍调用共同规则，不直接使用预测人数结算。

### A6.3 优先级二：扩张或进攻

对来源与非己方目标组合：

1. 按源营兵种计算派兵 S 与行军时间 T，并在公开状态的预测副本中估算沿途塔射损失。
2. 中立目标预计守军 D=当前驻军；有主非己方目标 D=min(容量, 当前驻军 + floor(产速 × T 秒) + T 前及同刻该目标阵营的已知增援)。
3. 若本方已在途、将更早抵达该目标的兵力已经达到 D+安全余量，则暂不重复攻击，等待新状态。
4. 只有预测抵达剩余兵力 ≥ D+安全余量 的组合进入评分，避免把同量清零误认成夺城。
5. 评分 = 100×是否中立 + 120×是否目标阵营最后据点 + 20×目标产速 − 8×T 秒 − 0.25×D。
6. 高分优先，同分按更短 T、目标 ID、来源 ID 依次决定。

目标在路上增援会让电脑攻击失败，允许这种结果，不读档纠正。评分不增加伤害或奖励。

### A6.4 优先级三：安全升级，然后调动后方储备

没有紧急增援或可行攻击时，先找安全升级：驻军达门槛、未来 8 秒公开预测无敌队到达或敌塔可造成的伤害、扣费后至少留 10 人；优先升级后自然产能提升更大的营地，再按 ID。升级一次即结束此次决策；不满足则检查后方调兵：

- 来源至少达到容量 80%，仍满足保留兵力要求。
- 目标是己方其他点，它到最近非己方有主城的距离比来源至少近 40 逻辑单位。
- 目标驻军 + 已知在途友军 + 本次 S 不超容量，避免主动浪费。
- 优先距离改善最大，再按行军时间、目标 ID、来源 ID；没有候选就等待。

如实际关卡长期僵持，应修改参数或决策并重测，不临时给电脑隐形属性。


## A7. 正式四方标准电脑

三个电脑首次决策 3 游戏秒、间隔 1.5 秒、进攻最低驻军 12、安全余量 2、防守窗口 4 秒，基础决策同 A6。对所有非己方阵营同样评分，没有 P 专属仇恨值。各自征召乡勇 1 张、无其他主动、被动 0 层，战前公开。

同刻从同一公开快照选择，每个电脑最多一个动作，提交再校验。防守预测允许保守合计敌军，实际交战仍用多阵营抵消，不准为电脑换伤害公式。阵营 ID 可以稳定启发式选目标，不能打破名次并列。

### A7.1 库存驱动的卡片优先级

1. 征召乡勇：4 秒内受袭且补最多 6 兵能避免预计被占领时使用，先最后城，再最早 ETA/目标 ID。有库存时下次可再补。
2. 测试显式提供火袭粮营时：己方来兵 4 秒内到达，且停产／停射能改变预计夺城或通过范围的损失时使用；续时须仍对本次行动有用。
3. 执行 A6 的增援／扩张／安全升级／调兵；测试提供倍道兼行时，仅在能缩短 ETA 时使用，否则普通出兵不浪费卡。
4. 测试提供鸣鼓征兵时：无更高优先动作，未来 4 秒安全、空缺至少 8，优先高产速/ID；已有鸣鼓征兵剩余超过 2 秒时倾向节约。
5. 无有效动作等待。不得免费补兵、刷新库存、读玩家手势或偷改产速。

标准配置只有征召乡勇 1 张，但给测试电脑 3 张必须支持三次合法决策各用一张。AI 间隔是行为节奏，不建立玩家共享冷却。跨周旧未用电脑主动同样到期，不重发；已生效效果按原期限收尾。
