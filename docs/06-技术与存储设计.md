## E1. 平台与数据边界

首发采用用户确认的 TypeScript＋Canvas 2D。规则代码与画面绘制在浏览器试玩和微信小游戏中共用，浏览器 DOM 只承载 Canvas 与必要可访问入口，不作为微信运行时依赖；存储、输入、音频、生命周期与开放数据域通过平台适配隔离。无运行时第三方游戏框架。开发检查和构建工具不进入运行包，版本锁定在项目包管理文件中；实际验证见开发计划。

微信构建使用 ES2015 启动壳 `game.js` 和 ES2020 `game-core.js`。启动壳先检查 BigInt，支持时才加载精确分数核心；不支持时仅显示更新微信提示，不读取或改写存档。降低编译目标不是旧设备兼容证明，最低客户端范围仍须以 iOS／Android 微信实机核验。音频通过可选 `wx.createWebAudioContext` 适配共用 GameAudio：触摸解锁等待异步 resume 后再播放首次点击，恢复期间已提交的战斗短音也等待；已处于 running 时立即播放。静音、暂停或隐藏停止声音并取消全部待播，换局或 restorationVersion 改变后不播放旧战斗事件。创建／恢复／播放失败（含恢复完成但仍不可播放）给出一次简短提示，设置“试听”以独立 240 ms 短音重试，成功后允许下一次故障重新提示；不覆盖用户开关，原生音频异常不得阻断输入或保存。无 DOM 的入口合同测试只验证调用与生命周期，不代替开发者工具或真机实际听音。

开发者工具使用 `compileType: "game"`，源码目录字段仍为 `miniprogramRoot`，与[微信官方小游戏示例](https://github.com/wechat-miniprogram/minigame-demo/blob/master/project.config.json)一致；`minigameRoot` 不是本项目使用的入口字段。根目录项目配置指向 `dist/wechat/`，独立构建目录配置指向 `./`。账号配置保留在根目录，构建仅重建产物，不改根目录 AppID。微信产物压缩、不生成 source maps，并清理以前生成的 game.js.map／game-core.js.map；两端 assets/art 输出按资源清单同步移除旧 JPG／PNG，源素材保持。构建结束统计微信输出目录全部文件，超过 4×1024×1024 字节即失败，不依赖开发者工具自动过滤或压缩。浏览器仍保留 source maps。

按微信小游戏交付，核心战斗/电脑/成长在本地运行。只引入官方好友托管成绩作为业务数据联网例外，不建服务端、账号系统、数据库、第三方统计、广告/支付 SDK。不得因为好友榜方便而上传全存档或收集通讯录。

只请求实际需要的平台能力；不请求位置、相册、麦克风、手机号、自由输入昵称等。游戏身份可用本地军旗名片，好友榜头像/昵称仅用平台允许在开放数据域展示的资料。拒绝可选好友能力不阻断本地核心；平台强制合规流程另依真实要求，不能绕过。

核心资源随包/官方可用加载链提供，首次下载资源当然需要网络；“离线可玩”指资源已可用之后的核心，不宣称从未下载也能启动。

原创图片由 `src/render/assets.ts` 的同一注册表管理，浏览器提供 `Image`，微信提供 `wx.createImage`；两端构建仅复制当前七项本地图片（首页、三种地表、七策图集、基础战场图集、步营／迈步样板图集）；营地与士兵使用透明图片并保留 Canvas 回退，退役图集不注册或加载。异步加载不等待或修改存档事务，15 秒未完成转为可重试失败，成功图片复用，旧加载回调失效。绘制不可用时回退简图；设置页与前台恢复可重试失败项。资源可用版本变化使旧手势和旧页面回调失效，保留已经明确选中的卡片；所有库存、兵数、文字和触控仍由代码产生。

## E2. 存档数据模型

独立命名空间 territory-conquest；本地 0.1.0 使用 schemaVersion 1、rulesetId tc-v1，contentVersion 记录具体包版本。单局 Battle.ruleRevision 区分 1.5／1.6；文档版本不表示已公开发布，当前需兼容已有本地 v1.5 对局，之后按 F7 版本化。未实现或未验收弓兵齐射的基础样例不能使用正式计奖／上传配置；后续攻城营储备不阻塞首发。早期无齐射状态或弓兵移速不同的实验快照不能直接按新规则续局。以下字段定义设计契约，实际实现与验证范围见开发计划。

| 数据组 | 必须字段/约束 |
| --- | --- |
| 存档封套 | schemaVersion、rulesetId、contentVersion、revision、writtenAt、校验摘要；摘要仅发现损坏，非防篡改签名 |
| 永久进度 | rankPoints≥0、highestRankPoints≥rankPoints（初始均 0）、tutorialFirstWins 集合、unlockedCardIds（与教学首胜／解锁表一致校验）、首次拖拽完成标志、formalCompleted≥0、settings |
| 永久周纪念 | 可选 weeklyRecord：archivedWeeks、totalWins、bestWins、lastWeekId、lastWeekWins；安全非负整数，周数大于 0，totalWins≥bestWins≥lastWeekWins，归档周早于当前周；旧档缺省无纪念，不伪造历史 |
| 当前周 | weekId、activeInventory 四 ID 非负整数、passiveLevels 三 ID 各非负整数且无游戏层数上限、qualifiedArenaWins；无被动里程碑字段 |
| 单局 | 一个 activeMatch 或空，matchId 唯一；battle.ruleRevision 为 1.5 或 1.6，新局默认 1.6；Match／Settlement 可选 meritPolicy，仅接受 growth-v1，缺省为旧计分。新局保存 growth-v1，旧局不改写，旧结果不重算；正式与临时无奖励练习分离 |
| 已确定结果 | matchId、settledAt、settlementWeek、结果/资格、settlementKind（natural/forfeit/technical_void）、rankDeltaRequested/rankDeltaApplied、rankPointsBefore/After、highestRankPointsAfter、奖励前后摘要、fixedChoices、resultAcknowledged |
| 待选 | choiceId、kind=mixed、固定 candidateIds／各自类型、unlockSnapshot／poolVersion、grantQuantity=1、pending/claimed/abandoned/expired；一局至多一个选择、只领一张 |
| 时间 | maxObservedWeek、maxObservedTime；不保存定位信息 |
| 榜单偏好/队列 | optedIn 默认 false、当前待同步最新分数、syncStatus、最近成功时间；不保存好友名单 |

promotionLevel 仅从 rankPoints 推导，不作为第二个持久化真相；highestRankPoints 只作纪念展示。历史最高/军功不得由托管胜场反推。不保存周职位、卡槽、perCardUsedOnce、共享冷却或永久被动。已处理旧局不无限保留日志：只留最新结果/待选与单局序列号高水位，旧回调必须同时满足当前局/当前事务，不能重放任意历史 matchId。主动数量或被动层数显示 999+ 不改变真实值；越界/非整数走损坏处理，不能溢出变负数。 已存数量仍为有效安全整数、仅下一次领取会越界时，选策预览不得抛错或改写原值；该候选提示“数量超出可保存范围”，可改选其他候选，不把未发生的溢出当成存档损坏。

同一设备同时只允许一个可恢复标准会话（正式四方或正常练兵）。没有正式待处理事项时，正常练兵也保存中途进度，modeId 隔离奖励。已有正式快照/待领，或存储故障时仍要练习，则明确进入独立临时无奖励会话：不消耗卡、不覆写原快照/待领奖，不写首胜/军功/历史最高；退出只丢临时练习局。当前无已发布玩家存档，不编造旧 v0.3 存档迁移。

临时练兵从暂停返回首页时清除临时会话引用，之后的续战读取原已保存对局；不把临时局继续挂在正式续战入口。没有可读资料时，暂停退出、弃战及战报返回均回恢复页并保留原损坏槽，不生成空白资料或把错误转换为正常首页。

A01 样板以同一节点／道路 ID 采用整体旋转坐标。新局使用当前地图种子；验证先检查全图是否与保留的原 A01 坐标完全匹配，仅完整旧布局才使用旧种子校验，其余必须全图符合新种子，禁止逐城任选新旧坐标。存量在途的 from／to、ETA、齐射和塔射状态原样恢复，不为美术更新改写存档。专项验证见 `tests/a01-layout.test.ts`。

v1.5 恢复继续使用原始自然生产（一级步／弓／骑／塔 1.2／0.8／0.8／0.4）、基础速度 80／上限 160、任意直达和旧 AI 节拍。v1.6 新局使用 0.9／0.6／0.6／0.3、24／48 及地图道路；不能只改快照版本号而重算在途速度／ETA。两版均验证兵种、真实几何、剩余人数、齐射一次性和事务资产；新局额外拒绝跨路兵团。未知版本或非法状态保留原记录进入恢复，不通过弃战或清零来兼容。自动边界见 [tactical-storage.test.ts](../tests/tactical-storage.test.ts)，不代表微信真机已验收。

## E3. 单局恢复范围

正常开局（正式四方或可保存练兵）保存成功才开始游戏时钟；明确降级的临时无奖励练习除外。检查点保存完整确定性状态：

- matchId、modeId、mapId、规则/配置版本、realStartedAt、startWeekId、gameMs、deadlineMs、nextEntityId、已处理输入序号、至少一次派兵标志；正式局 rankedCommitment=true，初始保存成功才生效，练兵为 false。

开局的 realStartedAt 使用本次事务已观察的 maxObservedTime，startWeekId 使用同份资料的 weekId，避免二次读取时钟跨毫秒或跨周后产生自相矛盾的快照；临时练兵的开局时间与周标也从同一次时间读取生成。
- 全部营地的 owner／type／tier／garrison／credit、城上效果期限及 remainingBonusBudget；type 唯一决定驻军兵种，不另存可分叉的混编数组。credit／预算的精确有理数以约分后的十进制字符串分子分母保存，分母>0；JSON 不直接序列化 BigInt。
- 全部有效兵团的 ID、阵营、troopType、initialCount／remainingCount、起终点、出发／到达游戏时刻、速度快照；当前人数可被塔射削减，零兵队不保留有效到达。
- 弓兵队另存 volleyCheckAtMs 与 volleyState（pending／fired／skipped）；skipped 另存 volleySkipReason（friendly／empty／zeroDamage），按友方→空营→零伤优先记录唯一原因，其余状态该原因为空；非弓兵不携带有效齐射状态。创建时 pending，唯一检查结束后记 fired 或 skipped；事件键为 matchId＋兵团 ID＋volley，不能只凭画面箭迹判断是否已射。准备时间不另存可独立漂移的倒计时。
- 各塔营 nextShotAtMs、射击序号／事件高水位及压制状态；当前等级、下一射击时刻和同刻结算阶段足以重建射击，视觉箭矢不存成伤害实体。
- 阵营存活/淘汰名次、开局被动层数／曲线版本快照、电脑剩余库存、下一决策时刻；有随机候选/配置时保存种子及状态。
- 已成功消费／升级后的状态和必要 actionId／actionKind；未确认拖拽、待选目标、特效、音频不恢复。

每 5 游戏秒存一个正常检查点，onHide 尽力立即保存；不能假定进程被杀前一定收到回调。消费、升级、正常教学首胜／解锁、终局、领取、切周、回首页是必须提交的事务，不等待下一周期。存档成功前不展示“已保存”。

恢复不补算后台时间，从最后一致 gameMs 继续；先进入暂停确认并清触摸、停声音。无经济事件的突发杀进程可能回退最多一个 5 秒检查点间隔（前提周期保存正常）；写入已失败时不能承诺此界限，须暂停并显示问题。已确认的主动消费及效果、升级扣兵及等级必须一起恢复，不出现库存扣了而对应兵团/效果从未存在。

浏览器 `visibilitychange` 隐藏与 `pagehide` 离开入口均立即取消输入、停止声音并暂停保存；离开时不依赖下一动画帧才停音。浏览器窗口隐藏不保证页面实际收到生命周期事件，验收须记录真实状态，不能以隐藏工具调用成功代替。

恢复资格：从 realStartedAt 起现实时间未超过 24 小时、结构/版本兼容且未终局。重复保存不刷新 24 小时起点。兼容且可信的正式快照超时后不自动扣分或发奖：提示“超过 24 小时不能继续，新局确认放弃不扣军功；旧局确认弃战扣 10 军功（最低 0）”；取消保留待处理项，下一正式局前必须确认弃战，不能丢快照绕过扣分。普通兼容旧局即使跨周，仍按其 meritPolicy／缺省旧策略结算，不补发周奖励。练兵过期丢弃不计分。已结算结果/待选遵循周规则，24 小时时效不撤销已结算军功。

技术不兼容不同于玩家弃战：先判断封套/规则能否可靠识别；已知 schema 中可识别原 matchId 和永久数据、但更新确实不再支持旧战场规则时，说明原因并确认 technical_void，军功 0、不发奖、不退已耗卡、不增加 c，保留原备份。未知 schema、损坏或写入未知先走恢复，无法可靠识别的结果不猜测扣分，也不直接删局开新正式；只能恢复兼容存档、用无奖励练兵或明确全量本地重置。没有“按一下报告故障免扣分”入口，不把联网失败或正常后台当技术作废。

返回首页默认保留暂停战场；“放弃并重开”须展示新局不扣分／旧局应扣 10 及实际扣分，已用策略不退款。以同一 matchId 保存 forfeit 结果＋军功变化＋清 activeMatch 后，才可进入新准备/新建 ID；确认失败留原局，不双扣。弃战确认已展示完整实扣前后值，成功提交时同步 resultAcknowledged=true，不再强制播放一次结果页；回调丢失后按已保存结果恢复，不再扣。正常练兵弃局 0 分。已自然终局优先恢复既有结果，不让弃战覆盖；结算中的放弃请求不生成第二份结果。最多恢复一局，不提供旧周构筑多个存档槽。

### E3.1 齐射几何、时间与恢复契约

参数与判定以主文档第 3.1 节为唯一来源。队首沿两城中心连线、源边缘至目标边缘插值，端点半径均为 18；显示、塔射和齐射共用该权威位置。令中心距为 D、路长 L=D−36，departAt 为出发时刻，T=arrivalAtMs−departAt 为已含速度上限／最短旅时的整数时长。当前合法地图 D≥64，所以 L>0。

- 相对出发的首次入射程时刻为 entryOffset=ceil(T×max(0,D−18−70)／L)。唯一检查时刻 volleyCheckAtMs=departAt+max(500,entryOffset)，且必须严格早于 arrivalAtMs；不用基础速度重新推算另一套位置。每队创建时计算一次、存档并按相同配置复核。
- v1.6 无加成、路长 200 的弓兵 T=8334，entryOffset=6168，故出发后 6168 ms 齐射、8334 ms 到达。中心距 64、T=1167 的短路线出发时已在范围内，仍等到出发后 500 ms；速度加成或缩放不取消准备时间。
- 用一致的确定性几何计算取得最早满足范围条件的整数毫秒，并复核边界；不得依显示帧轮询或把 70.1 当成 70。合法地图没有零路长；非法重合节点走配置校验，不靠除零后夹值放行。
- pending 事件加入生产／到达／塔射共用时间线。按主文档第 8 节先结同刻到达与淘汰，再塔射，再齐射；齐射批统一读取塔射后的状态，各队伤害按当前人数独立取整后按营地合计、截零。
- 已到达、零兵、阵营淘汰的队伍取消未执行检查；源易主但阵营仍存活不取消。射击时目标已己方／空营／伤害取整为零则转 skipped，不以后补射；合法正伤害候选转 fired，即使同刻合计溢出也不得转火或补发。
- fired／skipped 与目标受击后的完整战场在同一事件批一致保存。恢复 pending 必须满足 volleyCheckAtMs>gameMs；恢复 fired／skipped 必须已经到过检查时刻，不重排事件。非弓兵带有效齐射字段、已过检查仍 pending、时间与路径配置不符、跳过原因缺失／非法或未知状态，均走 E 的恢复／不兼容处理，不默认为尚未射击。
- 动画使用已确认事件表现总伤害，不持久化视觉箭矢；暂停不推进检查时间，后台不补射。恢复较早合法检查点只重放该点以后的完整世界，不把新目标血量与旧 pending 拼接。

## E4. 一致性和线性化时刻

只有一个串行存档写通道。候选实现为两个交替槽保存完整封套，写下一 revision 后重读校验，再发布到内存；恢复读取最高完整有效 revision。不能将“库存一个 key、战场另一个 key”当成原子事务。具体平台掉电/容量行为必须实现后验证，校验摘要不提供安全防作弊。

主动事务：在当前游戏时刻验证当前周、库存、目标、状态 → 计算“库存−1＋效果后完整战场”候选 → 暂停规则时钟并写一个完整事务 → 确认落盘后发布该状态与反馈。倍道兼行须先比较 D 规定 T0/T1，零时间收益整次取消；合法时库存、源兵扣除、新兵团是同一事务。存档失败明确未提交则均不发生；结果不确定重读 revision/actionId 再决定，不能盲目重试扣卡。

升级事务：先在当前时刻按主文档顺序结清到达／塔射／齐射／终局，重验己方、等级、门槛与当前驻军 → 计算扣兵／等级／容量／产速切换后的完整状态 → 同通道保存并按 actionId 去重。明确失败均不发生，未知先恢复；只发布已提交结果。升级不刷新生产余量、鼓令预算、已排定的塔射或在途齐射状态，不能一边显示新等级一边保存旧成本。

会话成功显式载入后递增运行期 restorationVersion；该标记不写入存档、不改变规则版本。画面与声音按对局身份和恢复标记隔离瞬态事件缓存，避免同局回退后显示旧反馈或吞掉新事件；普通暂停／继续不递增。

快照必须落在完整事件批次或完整动作提交之后；不得只保存“箭塔已扣兵”却未推进节拍，或“齐射已伤守军”却仍保留 pending。恢复不得在同一 gameMs 重射、重转兵或重收升级成本。规则校验包括 type／兵种匹配、三级范围、预算非负、有效队人数>0、射击事件归属、齐射状态／时间一致性、永久解锁与教学一致性；非法值进入恢复，不静默夹到新规则。

**动作归属周以串行事务接受且完成合法性检查的现实时刻为线性化点。** 等待队列中的动作到轮到它时重新校周。若接受时还是周日、写完成时已周一，提交过的旧周动作/效果先恢复，再执行切周使未用旧库存失效；不能扣卡后又把效果取消。这里没有允许周一新接受旧卡。终局归属首次确定结果的 settledAt，同样不能靠慢保存改周。

结算原子更新：terminal 结果＋activeMatch 清理／终态＋按 D 应计／实计军功及最高＋按资格 formalCompleted／周胜＋唯一混合固定候选／解锁快照／grantQuantity=1。正常教学首胜另在同一教学结果事务保存首胜和永久候选资格，不生成库存／被动层数。自然终局、弃战和技术作废互斥，只能有一个最终结果。领取原子更新 choice 状态与所选一项库存 +1 或层数 +1，不再改军功。切周原子更新周数据并保留允许收尾的 activeMatch 快照。

串行期间短暂冻结规则不是技能冷却；不丢第二个独立输入，待提交输入执行前重新验证。写入超过 150ms 显示轻量保存状态；持续失败或未知则保护性暂停，禁止后续消费、领取和新正式局。可重试或进入独立无奖励练习，不让用户在不确定库存上继续花卡。动画结束与网络回调均不能替代提交。

周期保存也走同通道；不得用旧周期快照覆盖较新的消费/切周。跨后台回来的旧 actionId、旧 matchId、旧上传请求不能污染新局/新周。新版本不能回退到旧规则后继续结算同一局。

## E5. 周界、时间异常与重置

weekId 用北京时间 UTC+8 每周一日期，不用设备所选显示时区。例如 2026-09-13 23:59:59 仍为 2026-09-07 周，2026-09-14 00:00:00 为 2026-09-14 周（UTC 对应 9 月 13 日 16:00）。

启动、回前台、继续、开局、每次消费/领取/结算前检查；前台运行也要触发周界处理，不等下次启动。一次跨多周只建立当前周，不补发中间周任何奖励。

周清空：未用主动、被动拥有层数、旧待选、周胜场。保留：军功、历史最高、教学及永久卡池解锁、formalCompleted、设置及 weeklyRecord（旧局仍可能依其开局约定降衔）。已启动被动/已用短效只随原 matchId 收尾，24 小时恢复资格仍适用；旧待施放取消。跨周后的本局结果记新周，公开提示“本局效果保留，成绩计入新周”。

现实时间早于已观察周时，不回滚数据、不重发选卡或回退永久解锁，提示校时并暂停正式经济/正式续战，可玩无奖励练习。同周小幅校时不扣分，maxObservedTime 保持单调用于恢复时效，防止反复回拨延长快照；不是可信反作弊系统。把时钟拨到未来可能提前到期，不能无后端却承诺准确识别真实时间或自动追回所有卡。

| 操作 | 确认内容 | 范围/结果 |
| --- | --- | --- |
| 放弃一局 | 新局正式弃战 0、旧局扣 10 最低 0；显示真实约定／前后值；已用锦囊不返还 | 一次保存弃战结果/军功并清该局快照，不清策略库；练兵 0 分，技术作废按 E3 |
| 放弃待选 | 本次机会不补发 | 仅标记对应 choice，不补发新机会 |
| 清除本地游戏记录 | 当前军功、历史最高、教学与永久解锁、策略、周进度、快照、设置全部清除且无法云找回 | 只清本项目命名空间；不清其他游戏或好友托管 |
| 删除本人好友榜记录 | 删除本游戏本人托管成绩；本地记录保留 | 需联网单独确认；成功后停止自动上传，重启也不马上恢复上传 |

本地重置开始时冻结经济写通道并更换本地会话 generation，使所有旧局/旧保存/旧网络回调失效；完成后才载入新空档。不能让在途回调把已确认清除的本地数据写回来。此 generation 仅用于客户端隔离，不是微信账号标识或防作弊身份。

损坏先保留原槽，检查备份；若只能恢复更旧版本，明确告知可能回退到记录时间，用户选恢复或重置，不静默改经济数值。未知 schema 不向旧格式写入，保留原档、提供更新/无奖励练习/明确重置。清本地和删托管不是默认组合操作，失败不能报成功。

## E6. 好友周榜产品规则

名称“好友周榜”，比较**本周标准四方独立冠军次数**，不是当前/最高军衔、军功、卡数、胜率、最快用时或资产战力。此榜是本地对电脑成绩的好友比较，不是真人互战，名次不给额外策略/现金/奖品。

读到的可展示范围由微信官方好友能力决定，不假定能读通讯录全部好友。只展示当前 weekId、modeId=arena-four、rulesetId=tc-v1 且数据合法的记录。旧周/不同规则不混榜；资料不可用显示默认旗，不猜测姓名。无当前记录的好友不造 0 分条目；“我”无记录时显示未上榜/本机 0 胜。

wins 降序，相同 wins 同名次，下一名跳过并列人数（例如 5/5/3 胜显示 1/1/3 名）；同分条目展示顺序可以稳定但不能给不同名次。仅显示前 50 条和独立“我的成绩”条；列表如平台返回不足按实际范围，不声称全量排名。头像姓名只在开放数据域使用/绘制，不回传原始好友列表到主域/日志/自建服务。

最小本人托管值设计：一个固定 key=territory_weekly_v1，value 包含 weekId、rulesetId、modeId、wins，序列化后目标小于 512 字节。周更替覆盖当前值，不每周无限新建 key；旧周好友记录由读取过滤自然退出，不替别人删除数据。

本机本周胜场是本地经济真相。托管仅保留同周本人已上传记录与本机记录的较大值，**不把两台设备的胜场相加**，也不据托管高分补发本机解锁／军功／历史最高／策略。换机/清本地可出现“好友榜记录 5 胜，本机进度 0 胜”，必须解释“榜单不是云存档”。同账户多端并发没有服务器原子比较与合并保证；首发提示以一台设备游玩，不宣称强一致跨设备高水位。

## E7. 周榜权限与同步回路

首次进入 S13：说明“开启后将本人本周冠军次数同步至微信，用于好友比较” → 用户主动开启 → 按平台实际要求授权/隐私确认 → 加载榜单。不开启可看本地个人周记录，不自动上传或反复弹授权。平台拒绝/无能力显示原因，可回首页继续离线对战。

开启后，先完成本地结算，再合并一个当前周最新同步任务；在结果页、进入榜单、回前台有网络时尝试。只串行一个请求；成功前不显示已更新，失败不阻断选卡/开局。手动刷新最短 3 秒间隔防误触请求风暴，是榜单请求节流，不是战斗冷却。

上传前在官方允许的上下文读取本人当前托管高水位并按 E6 合并；读取失败不盲写低分覆盖，保留待同步。一个会话失败后按 5/15/60 秒最多三次前台重试，之后等用户刷新/下一次回前台或新结算；后台不持续轮询。不保存无限失败队列，旧周待同步直接丢弃，旧响应不能更新当前周 UI；若旧写已在平台完成，随后当前周写修正，列表始终按周过滤。

页面状态完整区分：尚未开启、需平台授权、加载、成功、空榜、离线有本次会话缓存、离线无缓存、上传待同步、错误可重试、能力不支持/建议更新。会话缓存不得持久化原始好友名单；退出销毁展示资源。10 秒仍未完成显示可重试错误状态；旧请求回来须校验页面/周/授权会话，不弹过期成功。

设置“关闭好友成绩同步”立即停队列；已经托管的本人记录可能仍被好友看到，文案须明确，另提供删除入口。删除先停同步、串行等在途写结束再调用删除，避免刚删又被旧请求写回；失败保留停同步和重试按钮。以后重新开启须用户明确同意，不自动把清除操作撤销。只处理本人当前项目 key，绝不改好友数据。
