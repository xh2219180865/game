## ADDED Requirements

### Requirement: 产品定位

游戏 MUST 以“弹弹奇境”为原型阶段工作代号，面向中国大陆 18—40 岁休闲用户，采用竖屏单手操作和“夜游奇境 · 国风霓虹弹射”的视觉方向。

#### Scenario: 评审新增页面或功能

- **WHEN** 团队评审新增页面、功能或美术资源
- **THEN** 方案必须说明其如何服务竖屏单手操作、休闲用户和“治愈世界壳 + 高对比战斗场”的视觉基线
- **AND** 不得照搬纯工业霓虹、低幼表现或由 VIP、广告奖励和排行榜堆叠构成的传统手游大厅

### Requirement: 核心体验

游戏 MUST 以“瞄准一次触发整屏连锁”和“每三回合选择一次弹珠能力”为核心差异化，并将普通单关目标时长控制在 1—3 分钟。

#### Scenario: 完成一次核心关卡循环

- **WHEN** 玩家进入普通关卡并完成三个回合
- **THEN** 玩家必须经历观察、瞄准、发射、连锁反馈、回收和回合推进
- **AND** 系统必须展示三个候选能力供玩家选择一个
- **AND** 关卡必须具有明确的胜利或失败结果

### Requirement: MVP 范围

MVP MUST 包含交互式教学、主页、章节入口、游戏主界面、能力三选一、胜负结算、每周挑战与微信好友周榜、弹珠精灵收集、轻量场景成长和基础设置。教学、设置、能力与奖励 MAY 以同页状态或轻量弹层承载，不要求每项功能独立成页。

#### Scenario: 评估 MVP 是否完整

- **WHEN** 项目申请进入首次外部测试
- **THEN** 所有 MVP 必做模块必须存在可走通的主流程
- **AND** 声音、音乐、震动和隐私入口必须可访问

### Requirement: MVP 范围控制

原型阶段 MUST NOT 实现实时多人、复杂世界排行榜、大型成就系统、完整付费商城、多币种经济、公会、聊天、用户生成内容、插屏广告或 Banner。

#### Scenario: 提议非核心增长或商业化功能

- **WHEN** 有人提议在原型阶段加入上述非核心系统
- **THEN** 该功能必须被移出当前里程碑
- **AND** 只有核心重玩率和留存得到验证后才能另立变更评估

### Requirement: 轻量本地运行

核心游戏 MUST 使用本地配置和本地存储运行，MUST NOT 依赖自建后端、云函数、云开发数据库、完整云存档、远程配置或第三方数据/分析 SDK，MUST NOT 建立自有登录账号、世界排行或跨设备进度同步。微信好友周榜 MUST 仅使用用户已允许的微信官方托管数据与开放数据域。该约束针对游戏运行时业务，不限制 Figma、Cocos 等制作工具。

#### Scenario: 完成基础游戏循环

- **WHEN** 游戏包与本地资源已可用，玩家开始、重试或完成关卡
- **THEN** 核心游戏不得要求自有账号登录或业务服务器，好友榜未授权或不可用不得阻断游戏
- **AND** 教学、关卡、能力与奖励规则必须由本地内容提供

#### Scenario: 保存和恢复进度

- **WHEN** 玩家完成教学、回合检查点、关卡或修改设置
- **THEN** 关卡进度、解锁内容和设置必须仅保存在当前设备，只有好友周榜必需成绩可托管至微信
- **AND** 存档损坏时必须提供可继续游戏的重新开始路径，写入失败时必须提示未保存风险且不阻断当前关卡
- **AND** 设置必须说明本地保存与榜单托管的不同范围；本地重置前必须确认，不得声称本地重置同时删除微信托管成绩，必须按平台能力提供榜单数据清除路径
- **AND** 清理本地数据或换设备后不得承诺恢复关卡或收藏

### Requirement: 每周挑战周期

每周挑战 MUST 使用北京时间（UTC+8）周起始日与内置内容版本派生的确定性种子，每周一 00:00 切换。周榜 MUST 仅比较同周、同版本成绩，不提供世界排名或强防作弊承诺。

#### Scenario: 重玩本周挑战

- **WHEN** 同一内容版本和相同北京时间自然周再次进入每周挑战
- **THEN** 初始挑战配置必须可复现，并读取当前设备的本周个人最佳
- **AND** 周标识或版本变化由本地规则处理，不请求服务器时间或远程种子

#### Scenario: 跨周切换

- **WHEN** 玩家在北京时间周一 00:00 后进入或恢复游戏，检测到周标识已变化
- **THEN** 必须启用新周挑战和空的本周成绩，同时保留章节进度、精灵、场景和设置
- **AND** 跨周进行中的一局必须保留开始时的周标识，其成绩不得计入新周
- **AND** 不得为切周要求游戏后台常驻或清空完整本地存档

### Requirement: 微信好友周榜

好友周榜 MUST 仅通过微信官方托管数据与开放数据域展示平台可返回的同玩好友成绩，不建立自有账号、业务数据库或世界排行。托管数据 MUST 限于周标识、内容版本、最好成绩及必要更新时间，不同步完整存档或另建好友档案。

#### Scenario: 查看本周排行

- **WHEN** 玩家进入好友周榜，平台所需授权与数据读取成功
- **THEN** 必须按统一计分规则展示每位同玩好友在本周、同版本下的最好成绩，同分默认并列
- **AND** 必须标明本周周期与自己的成绩或未参赛状态，不得将不同版本、往周成绩混入或伪造好友条目
- **AND** 头像昵称必须在平台允许的开放数据域内展示，不另行采集或上传至其他服务

#### Scenario: 授权拒绝或数据不可用

- **WHEN** 玩家拒绝所需授权、没有有效好友成绩、离线或榜单请求失败
- **THEN** 必须分别展示未授权、空榜或不可用状态，并允许直接返回游戏
- **AND** 成绩上传失败必须保留本地最佳并允许后续重试，不阻断关卡开始、重试或结算
- **AND** 旧周或旧版本的待同步成绩不得覆盖当前有效记录

### Requirement: 设计优先门禁

项目 MUST 在独立 Figma 文件中完成并确认核心流程后，才可启动新的 Cocos Creator 工程。

#### Scenario: 申请开始 Cocos 灰盒

- **WHEN** 准备创建 Cocos Creator 工程或写入新的游戏运行时代码
- **THEN** 必须确认产品说明、用户流程、核心低保真页面、游戏主界面高保真方案和可点击主流程已通过评审
- **AND** Figma 文件不得写入其他产品的设计系统文件

### Requirement: 页面体验验收

页面设计 MUST 以目标理解、操作反馈和完整重玩流程验收。视觉稿、交互演示与真实游戏手感 MUST 分别验证，画板数量和截图检查不能替代交互验收。

#### Scenario: 首次进入和第一发

- **WHEN** 未读说明的测试者在资源就绪后第一次进入游戏
- **THEN** 走查必须检查其能否在约 3 秒内辨认目标和主操作，并通过第一发完成情境教学
- **AND** 每屏必须有明确主操作，文字、图形与可点击范围不得因小尺寸手机或微信胶囊而不可用
- **AND** 尚未实际走查的目标必须保持待验证状态

#### Scenario: 验证一局完整流程

- **WHEN** 走查首页、瞄准、发射、连锁、能力选择和胜负结果
- **THEN** 所有画面必须使用一致的玩法规则、目标数值和角色表现，三个候选能力必须都能完成选择
- **AND** 结算必须连接下一关、直接重试和返回等适用路径；教学、暂停、奖励优先复用同页状态或轻量弹层
- **AND** 碰撞与连锁反馈不得遮挡关键目标，并必须清楚表达反馈结束后的下一步

### Requirement: Phase A 视觉与情绪体验基线

Phase A Figma 原型 MUST 采用“夜游奇境”的东方夜色方向：以现代化、几何化的东方自然元素建立治愈世界，以深紫黑竞技场和严格单一语义的青色玩家、黄色目标/主行动、红色危险建立玩法刺激度。主游戏内容 MUST 始终是页面第一视觉焦点，界面不得退化为白色卡片、纯色胶囊、纯工业霓虹或传统手游大厅的堆叠。

#### Scenario: 评审首页吸引力

- **WHEN** 新用户首次看到首页
- **THEN** 页面必须在 1 秒内通过弹射场景、章节进度和奖励承诺说明核心玩法与当前目标
- **AND** 页面必须提供一个明确主 CTA，次级入口不得超过两个
- **AND** 除微信胶囊外，首页强描边容器不得超过两个，次级入口不得与主 CTA 使用同等视觉重量
- **AND** 原型阶段不得用 VIP、广告奖励或复杂排行榜作为主要吸引物

#### Scenario: 评审核心游戏高保真

- **WHEN** 评审瞄准、发射、碰撞和连锁页面
- **THEN** 页面必须展示具有轻生命感的玩家弹珠和属于奇境环境的目标物
- **AND** 竞技场边界、轨迹、目标耐久数字和状态必须保持清晰可辨
- **AND** 发射后非关键 UI 必须主动弱化
- **AND** 常驻战斗信息必须收敛为比分、回合、竞技场、目标和弹珠，解释性状态不得长期占据战场
- **AND** 原型必须区分普通碰撞、连续碰撞、明显连锁和整屏连锁四级反馈
- **AND** 整屏连锁必须通过轨迹、碎片、目标破裂和顶部小型连击数表达，不得用中央大字、圆环或遮罩遮挡竞技场
- **AND** 整屏连锁期间仍须保留竞技场、弹珠和目标的空间关系，并在高潮后快速恢复清爽状态

#### Scenario: 评审 V4 三色层级

- **WHEN** 评审首页、瞄准或整屏连锁标杆页
- **THEN** 青色必须只代表玩家弹珠及其轨迹，黄色必须只代表目标、命中与主行动，红色必须只代表危险或失败
- **AND** 静态画面不得出现第四种高饱和玩法色
- **AND** 页面第一眼必须能明确识别唯一主焦点，不得出现三个以上同等视觉重量的强容器

#### Scenario: 评审每三回合能力选择

- **WHEN** 玩家完成第三回合并进入能力三选一
- **THEN** 页面必须以“奇遇降临”作为世界观表达
- **AND** 三个能力必须成为唯一视觉中心并在 3 秒内可理解
- **AND** 页面不得采用 SSR 卡牌、金边、稀有度颜色轰炸或复杂 RPG 属性表

### Requirement: 微信竖屏与性能适配

Phase A 原型 MUST 明确覆盖微信右上角胶囊、顶部与底部安全区、单手触控和中低端安卓性能限制。

#### Scenario: 走查核心竖屏页面

- **WHEN** 在 375×812 基准画板及小尺寸安卓比例上走查页面
- **THEN** 关键 CTA 必须位于单手可达区域且不与系统胶囊或底部安全区冲突
- **AND** 主要文字必须保持适合 18—40 岁用户的清晰度
- **AND** 视觉方案不得依赖实时重度模糊、全屏持续粒子、多层光照或大量透明叠加

### Requirement: 工程实现基线

Cocos 灰盒 MUST 使用 TypeScript、固定时间步、配置化关卡与能力、确定性随机种子和对象池，并提供高速小球碰撞保护。

#### Scenario: 验证首个可玩灰盒

- **WHEN** 灰盒在微信真机环境运行
- **THEN** 瞄准、顺序发射、墙体反弹、砖块碰撞、扣血消除、首球落点回收、回合推进和胜负判断必须可用
- **AND** 必须包含一种分裂能力、一种连锁能力和快进或召回机制
- **AND** 帧率波动不得导致明显穿透或重复碰撞

### Requirement: 旧原型隔离

项目 MUST 以新产品规格作为唯一事实，不得继续承载旧“弹弹消消乐”原生 Canvas 实现及其增长、广告和经济系统。

#### Scenario: 发现旧原型内容

- **WHEN** 仓库中发现旧运行时代码、微信工程配置、旧资源或旧功能规格
- **THEN** 必须将其删除而不是继续扩展或迁移
- **AND** 后续运行时代码只能在 Phase A 验收通过后通过独立变更创建
