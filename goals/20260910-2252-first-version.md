## 文件职责和架构

- `src/core/`：与渲染和平台无关的 TypeScript 规则、精确生产计算、地图、电脑预测、策略成长；不调用 DOM、微信 API 或外部网络。
- `src/app/`：串行会话事务、存档恢复和页面状态协调。
- `src/platform/`：浏览器／微信存储、生命周期、输入、音频、官方好友榜适配，核心规则不依赖平台。
- 用户已选择 TypeScript＋Canvas 2D。`src/render/` 共用 Canvas 绘制与命中区域；浏览器和微信复用相同规则／画面，平台入口独立。无运行时第三方依赖；TypeScript 与 esbuild 仅作为开发检查和打包工具，不引入 Cocos 编辑器。
- `tests/`：规则、经济、恢复与适配测试；`scripts/`：受控的开发、构建和检查入口。`goals/` 保存本施工清单；项目总体状态仍以 `docs/10-开发计划.md` 为准。
- `.tmp/first-version/`：本次检查截图、临时日志等可重建材料，忽略提交；正式交付不依赖此目录。
- 接口原则：输入为带唯一 ID 的显式动作，模拟以整数游戏毫秒推进并输出事实事件；保存状态完全可序列化。生产采用有理数，营地单一驻军数，在途兵种与速度快照不回算。

## 关键边界与预期

- 事件顺序：生产／效果到期 → 全批到达／转换／淘汰 → 同刻塔射 → 同刻齐射 → 胜负／截止 → 玩家输入 → 同快照电脑。
- 弓兵产速 0.8、移速倍率 1.0；距目标中心 ≤70 且出发 ≥500 ms 首次检查，伤害 floor(3×当前人数／10)；友方／空营／零伤跳过并结束机会，不重复射击。
- 塔射先减在途人数；清空驻军不占领；零城立即取消在途；同刻交换最后城按最终归属判定。
- 所有升级、策略、结果和领奖操作按唯一 ID 去重；明确保存失败不发布效果，未知写入先恢复完整状态；不将坏档静默重置或补发资源。
- 任何需要真实账号、系统安装、外部写入或不可逆操作的步骤遵循当前用户授权和工具审批。先完成不依赖这些条件的工作。
