# 手机小游戏操作流程优化

目标：落实用户确认的六项方案，保留方案 A 青瓦城关，消除整页阅读和大按钮导航主导的体验。完成完整「首页 → 出征 → 调兵／用策／升级 → 结算／领奖」及其他必要页面。既有玩法、经济、存档、平台权限不变。不提交、推送或正式发布。

## 验收清单

- M1 首页：一个突出出征动作，已完成首课且无待处理事项时直接开始正式局；练兵／策略／周榜／军功／设置是有文字辅助的小图标入口。未确认结果、待领卡、已有局、错误和新玩家仍按原优先级处理。重复点击不得多开局。
- M2 战场：保留地图主体和既有路网，暂停图标化，非必要说明默认不常驻；首次操作提供短指引。主动卡可以直接从卡栏拖到合法城池，或点选后点目标；兼行拖到己方源城仅进入待发状态，随后拖兵才消费。拖到空白／敌我错误／UI区域／取消／后台／跨周／换局均零错误消费。原四卡可直接改选、取消。
- M3 升级：点城就地浮出紧凑操作卡，收益／消耗／差额清晰，不进专门升级页。卡不盖己方源城，不越安全区、不穿透，详细参数只通过小信息入口查看。成功保存后即时升级反馈与收起；存储失败、重复点击、旧等级回调不误扣兵。
- M4 策略：卡册展示卡面、库存和一句效果；详情是原页面上的小浮层，首屏短说明、按需完整规则，关闭恢复同一位置，无整页跳转或大号返回按钮。安全触区至少44 px；完整规则、锁定原因、精确数量和周界可查询；只读不写档。
- M5 结算：短动效表现胜败／军功／真实奖励，减少动态静态显示；动作不被动画锁住。领奖／再来一局突出，首页／战绩是次要入口。领取单选原子事务保留，关闭待领奖页不丢机会，失败／并列／无有效派兵／练兵不得伪造奖励。
- M6 全局：圆润游戏按钮与统一图标，减少整行矩形次要按钮，短说明与首次引导替代默认长文。暂停／设置／军功／教学／恢复必要流程仍完整；长规则、错误和不可逆操作说明不可裁掉。
- V1 自动：新增行为和故障路径测试，既有断言只有在真实交互合同变化时更新，不能删除保护。npm run check；微信输出<=4 MiB且重复构建不混入旧资源。
- V2 真实显示／输入：320×568、375×812、430×932主要页面及安全区检查；独立内存验收完整出征、拖卡有效/无效、升级、返回浮层、结算领奖，浏览器日志无新增错误；不改真实试玩存档。
- V3 微信：两端构建与已授权开发者工具自动预览通过。真机实际体验需用户手机反馈，不冒称代替真机听音/触摸验收。用户提供手机发现继续作为缺陷处理。

## 所有权与并行任务

主 Agent：src/render/game.ts、src/app/session.ts（仅必要入口）、现有集成测试、平台只在确证输入问题时修改。负责 M1-M6 布局、输入、经济边界集成、文档、预览和最终验收。公共状态／接口主 Agent 决定；不由子任务猜测产品逻辑。

### T1 游戏图标

目标：提供新的纯 Canvas 图标，支持小入口与图标按钮，减少网页式文本按钮。入口 art.ts 和 scheme-a.ts 供配色参考。
只允许新建 src/render/mobile-icons.ts、tests/mobile-icons.test.ts。导出类型 MobileIcon='settings'|'lessons'|'cards'|'leaderboard'|'rank'|'close'|'back'|'info'|'upgrade'|'home'|'replay'|'play'|'pause'|'chevron'；drawMobileIcon(ctx,x,y,size,icon,color?)，x/y中心，size总边长。青绿／暖白／朱红可配，轮廓笔画≥size*.07，图标形状可读，无文字／图片／状态依赖，save/restore平衡。圆底与标签由主 Agent处理。测试有效图标不同、尺寸边界、非有限值安全，最终真实浏览器由主 Agent验证。不得改共享文件或依赖。

### T2 就地浮层布局

目标：让升级卡贴近选城且不挡源城拖拽，边界稳定。只允许新建 src/render/mobile-layout.ts、tests/mobile-layout.test.ts。
导出 placeCampPopover(anchor:{x,y},bounds:{x,y,w,h},obstacles:readonly {x,y,w,h}[],size:{w,h}):{x,y,w,h}。bounds为战场安全区域（不含顶部/卡栏）。优先上／下／左右的候选，与源城中心周围半径34的矩形保持至少8间距；优先不遮其他营地，再按距anchor排序；同输入同结果，夹在bounds内，不能产出NaN。正常viewport320/375/430、当前540比例地图都应容纳宽min(248,bounds.w-16)、高124卡；如果空间极端不足可返回最大合法卡，但不能虚报无遮挡。主 Agent处理绘制、阻挡命中和隐藏卡。测试边缘/中央/拥挤/变尺寸/冻结输入、常规源城不遮挡、候选最少遮挡与确定性。不得改规则或主渲染。

### T3 输入与交互审查（后续检查点）

只允许新增 tests/mobile-gesture.test.ts，复用 tests/mobile-flow.test.ts 的独立内存会话模式，不修改共享文件。验证已接入的卡片直接拖放：兼行拖己城仅待发且后续合法派兵才消费，错误目标、UI、取消、后台、换局与跨周不误消费，点选方式仍可用。依据现有公开 GameView 输入与 GameSession API，关键失败路径需真实写入计数/库存断言；执行该文件测试，报告代码问题和证据，由主 Agent 修复。
