# v0.2 附录 B：页面、交互与动效规格

状态：待批准的制作规格，**不是已完成的 Figma 或视觉验收**。玩法以[主文档](../design.md)为准，参数不是成品审美的替代物。正式主题尚未确定。

## B1. 设计信息架构

M0 从教学战斗直接进入；M1 才加最小首页、三关选择和设置。暂停、详情、教学、胜负优先复用同一战场的状态/浮层，不要求每个状态独立成页。

| 页面 ID | 页面/状态 | 阶段 | 常驻信息 | 主动作与退出路径 |
| --- | --- | --- | --- | --- |
| S00 | 资源准备 | M0 | 实际加载状态，失败时明确原因类别 | 失败重试，不伪造加载百分比 |
| S01 | 最小首页 | M1 | 暂定游戏名、可玩的关卡/本次会话进度 | 开始游戏；次入口关卡、设置 |
| S02 | 战斗 | M0 | 我方/电脑据点数、关卡目标、战场、暂停 | 拖拽派兵；点击据点查询 |
| S03 | 暂停/后台恢复 | M0 | 当前关卡、暂停说明 | 继续；重新开始；M1 可返回首页 |
| S04 | 胜负/平局 | M0 | 真实结果与原因、用时（暂停不计） | 胜利下一关；失败/平局重试；可返回 |
| S05 | 三关选择 | M1 | 3 关名称、会话内通关/未解锁状态 | 选择可玩关，返回首页 |
| S06 | 设置 | M1 | 已实际实现的声音/震动/减少动态选项 | 修改即生效，关闭返回来源页 |
| S07 | 存档异常/重置确认 | M3 | 保存范围、失败风险、重置后果 | 重试保存或临时继续；重置需确认 |

M0 的 L01 胜利主按钮是“再玩一次”，不提供还不存在的下一关。M1 的 L01/L02 胜利提供下一关，L03 为“再玩一次/返回关卡”；禁止死链接和假解锁。

M1 的关卡 2 在通关关卡 1 后、关卡 3 在通关关卡 2 后于当前进程内解锁。未持久化时明确“本次体验进度仅本次运行有效”；未来 M3 再改为本地进度。开发调试跳关不作为玩家入口。

## B2. 战斗屏空间分配

基准检查画幅 375 × 812，另外检查 320 × 568 和 430 × 932。它们是布局测试尺寸，不是声称所有微信设备已适配。

- 顶部避开平台安全区与右上系统胶囊，左侧暂停、中央关卡/目标，右侧不放冲突按钮。
- 顶部只显示我方和电脑据点数量，不堆叠总战力、币、体力、卡槽、榜单。
- 中部为 360:540 比例的逻辑战场，以可用宽高的较小缩放比等比放置；多余空间留给背景，不拉伸规则坐标。
- 底部是简短操作提示/选中信息区，不铺满常驻派兵按钮。保留底部安全区。
- 据点触控目标在屏幕逻辑尺寸上至少 44 × 44；字体独立保证可读，不简单随战场缩到看不清。
- 驻军数字建议不小于 16 px，辅助说明不小于 13 px；若小屏空间不足，优先去掉装饰、缩短文案，不先缩小数字。
- 触控区重叠时不能靠创建顺序随机选择；须先修正布局。可见路径与关键城池不能被详情浮条遮挡。

## B3. 据点组件

每个据点包含四层信息：

1. 类型轮廓/图标：兵营用营帐或兵旗，堡垒用城墙，驿站用路标/箭头；均需原创。
2. 阵营：玩家、电脑、中立采用不同颜色加旗帜/符号，不只依赖红绿差异。
3. 驻军：最醒目整数；轻点查看容量、产速、速度倍率，以及可见来援/来敌数量和最近到达时间。信息条放在底部，不能仅向电脑提供这些行军信息。
4. 等级：稳定 I/II 标记，不用金币、星级稀有度暗示付费。

状态包括默认、选中、可派兵目标、不可派兵、被攻占、最后据点、容量满。叠加优先级为终局 > 受袭/最后据点 > 选中 > 普通装饰，不能画多层同等强度光圈。

## B4. 战斗状态与文案

| 状态 ID | 进入条件 | 视觉/文案 | 输入规则 |
| --- | --- | --- | --- |
| B00 | 首次 L01 等待教学派兵 | “拖到这里，派出一半兵力”与一个手势 | 模拟冻结，仅接受指定教学派兵 |
| B01 | 常规可操作 | 兵力、阵营、路上兵团；无教学时不常驻长说明 | 可拖拽、查询、暂停 |
| B02 | 按住己方据点 | 选中描边，“派出 X / 留守 Y” | 以松手时数据为准，数字随生产更新 |
| B03 | 拖到有效目标 | 单条箭线、目标高亮、预计到达时间 | 松手提交；不要显示保证必胜 |
| B04 | 拖到无效区或源点易主 | 清楚撤掉可提交高亮；不足兵时轻提示 | 松手取消且不扣兵 |
| B05 | 行军 | 队伍方向、归属和兵团数量 | 可继续派兵，不锁屏等动画 |
| B06 | 增援或交战到达 | 数字更新；单次扣兵/增援反馈 | 按实际逻辑结果绘制 |
| B07 | 成功占领 | 建筑换阵营、旗帜切换，剩余兵力清楚 | 未终局时可立即继续操作 |
| B08 | 只剩最后一个据点 | 稳定“最后据点”小标记 | 不额外暂停或加防御 |
| B09 | 有敌军前往最后据点 | 路线/标记短提醒，“最后据点受袭” | 不断言必败，不遮挡回防 |
| B10 | 已确认终局 | 冻结战斗，短反馈后进入结果 | 取消未提交拖动，不再派兵 |

第一次失守普通据点可短提示“该据点已被占领”；不要播放与整局失败同样的全屏表现。

## B5. 胜负、暂停与异常

- 胜利标题“本关胜利”，原因“敌方最后据点已被攻占”；不要求玩家继续清中立。
- 失败标题“本关失守”，原因“最后一座据点被攻占”；不因在途仍有兵而继续展示反攻倒计时。
- 平局标题“同时失守”，原因“双方最后据点同时被攻占”；必须有直接重试。
- 用时只作过程反馈，当前不是好友榜计分；不提供伪造胜率或好友成绩。
- 暂停先冻结再弹层。重新开始/返回首页在有未完成战斗时提示会放弃本局；返回取消原拖拽，不自动出兵。
- 资源失败不显示无限转圈，提供重试。尚未实现声音或震动时，不展示能切换却没有作用的假控件。
- 未实现持久化时不展示存档成功；写入失败后可继续游戏，但明确本次进度可能丢失。
- 本地重置须区分关卡与设置，明确不等于删除微信托管成绩；不实现未验证的云端清理按钮。

## B6. 动效预算表

以下为目标时长，以试玩调整；逻辑立即生效，动画只解释结果。

| 事件 | 建议时长 | 表现 | 不允许的行为 |
| --- | --- | --- | --- |
| 按下/选中 | 60—100 ms | 小幅缩放或描边出现 | 改变触控边界、遮挡数字 |
| 路线目标变化 | 跟随输入，过渡不超过 80 ms | 单线与箭头 | 全图自动连线、指针明显滞后 |
| 派兵成功 | 100—180 ms | 出发点轻反馈，兵团立刻出现 | 等排队动画结束才扣兵 |
| 行军 | 与逻辑进度同步 | 少量小兵/尾迹 | 给装饰随机速度造成假到达 |
| 增援/扣兵 | 100—160 ms | 数字跳变、短小增减提示 | 用持续跳字拖延真实数值 |
| 占领 | 220—320 ms | 旗帜易主、建筑换阵营 | 大字盖战场或重复触发伤害 |
| 最后据点受袭 | 200—350 ms | 局部描边强调一次 | 持续闪屏；同据点 3 秒内重复强提醒 |
| 暂停/结果弹层 | 150—220 ms | 简单淡入、轻位移 | 动画期间后台继续战斗 |
| 终局到可重试 | 目标不超过 600 ms | 短收束后主按钮可用 | 为庆祝强制等数秒 |

音效最多区分点击、出兵、到达、占领、胜/负几个类别；同刻多到达做合并/限频，不能每个装饰小兵播放一次。震动可关，不成为理解结果的唯一方式。

减少动态模式取消弹跳、长尾迹、震屏与循环强调，保留即时数字、阵营变化、静态受袭标记和主按钮。音效与减少动态互不替代。

## B7. 原创美术最小清单

| 资源 | 数量/变体 | 优先级 |
| --- | --- | --- |
| 据点基础轮廓 | 兵营、堡垒、驿站 3 套；各 I/II 简单细节 | M0 先兵营 I，其余 M1 |
| 阵营标记 | 玩家、电脑、中立 3 类，可复用换色与符号 | M0 |
| 基础兵团 | 1 种兵力外形，阵营变体；不做三兵种动作库 | M0 |
| 路线/选中/易主反馈 | 线、箭头、描边、旗帜动画 | M0/M1 |
| 地图背景 | 1 张干净背景或程序底色，3 关通过布局区分 | 正式主题确认前只用灰盒 |
| UI 图标 | 暂停、继续、重试、返回、设置与已实现开关 | 按实际功能制作 |

不直接导入参考截图、历史水墨卡牌和旧弹球资产。先明确新轮廓、材质、排版与色彩分工，再做正式资产；不把换色当作独立视觉已经完成。

## B8. Figma 与真实体验验收

后续 Figma 应至少覆盖 B00/B01/B03/B07/B09、暂停及三种结果；同一组画稿使用一致规则数值。原生动效或跳转不能冒充真实兵团、电脑和存档实现。

检查实际小屏数字、触控、胶囊/安全区、单手操作；再用真实运行时检查输入响应、行军可读性、误触和重试。帧率、内存、耗电和微信后台行为均须真机记录，静态截图不能替代。
