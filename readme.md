# 谋定山河

轻量三国主题城池争夺微信小游戏，竖屏单手操作，首版为玩家＋3 个电脑。“谋定山河”为当前工作名称。

**本地第一版可试玩。** 版本 0.1.0，新局规则 v1.6。已实现三关练兵、三张正式地图、四类营地、电脑、七策、军功、周重置与本地恢复。画面采用古代战争与青灰城关主题：首页为出征前庭、七策军令图鉴、十二款分级手绘营地、三种战场地表，四兵种采用甲胄、武器与坐骑轮廓清晰的手绘军士，图片异常保留 Canvas 回退；阵营色驻军牌、稳定跟队数字与受击减员提示共同呈现真实人数。浏览器可直接试玩；此前微信开发者工具已检查首页、卡册、详情与暂停恢复；七项图片资源包此前已通过自动预览；当前构建目录约 3.44 MiB，微信模拟器已实际验证拖兵、暂停恢复、三级升级、首关通关及 A01 正式局四分钟截止结算；四主动策略已在独立微信测试包中实操，库存恢复及兼行／三种被动领奖重载已验证，神速／扩营领取后的下一局加成已核对；胶囊坐标缺失时增加顶部避让，真机仍待验证。数值仍是待系统性平衡测试的基线。

A01 战场样板已接入：地图斜向排布、中央石坪与自然院落，步兵营采用木栅营／门楼院／双塔堡三级轮廓，四兵种均以六帧按真实行进距离迈步，军旗和准确兵数合并为近身跟队牌。旧局保留原地图位置，新局使用新布局，既有道路旅时和塔射覆盖关系保持；A02 冷灰冻土与 A03 暖砂石院落已统一，节点与连通保持。来源和检查入口见 [A01 战场样板](artifacts/ui-direction-v2/battle-sample.md) 与 [兵种动作记录](artifacts/ui-direction-v2/troop-motion.md)。

四类营地现均采用“小营／院落／双楼堡”的递进轮廓，地图移除常驻等级标签和营地旗帜，以屋面配色及同色驻军牌区分阵营。中立营地使用灰瓦灰墙及冷灰驻军牌。满足条件的己营在对应檐角显示约 10px 无底牌升级箭头，44px 触区向外扩展；轻点直接升级，从标识处拖动则派兵。部队仍保留队旗。行军标牌按出发人数固定宽度，真实减员时更新当前数字和命中提示。战场采用浅赭旧绢地面、青灰山林河岸与窄土路，景物不增加地形阻挡，道路仍对应真实连通。

练兵入口采用城关背景中的三处木绢演武关目，一键进入／重玩，小屏可滚动。设置采用城关／冻结战场上的木绢面板、铜木开关，关闭回到来源，对战不会自动继续。玩法说明默认展示派兵、升级和锦囊操作图解，完整九节规则按需查看。首页有云气、少量落叶和火盆光变化；“减少动态”保持静止。声音是操作与战斗短音效，尚无背景音乐；声音开启时可在设置点击“试听”，播放失败会提示重试。已修复异步恢复前首次点击声丢失，但用户报告的手机全程无声与缺失动效仍待真机定位；浏览器画面与自动测试不代替真机听音和体验验收。

策略图鉴采用四主动、三被动的两排军令入口，只介绍策略；已解锁正常显示，未解锁为灰色并可查解锁条件，不显示个人数量或领奖入口。图鉴说明仅显示效果、对象和解锁条件，完整规则按需展开。个人精确库存、被动层数与真实增益可从战前七策入口和军情中查询，奖励仍从首页／结算领取。内页统一首页城关底景、木匾标题、木框旧绢与朱漆动作；本轮已完成四尺寸浏览器检查，微信真机触摸与视觉仍待验。

## 本地运行

使用 Node.js 24 或以上版本，在项目目录运行：

```sh
npm ci
npm run dev
```

打开 [本地试玩](http://127.0.0.1:4173/) 。按住己方营地沿相连道路拖到相邻营地派出一半兵，轻点查询产兵速度与容量，点建筑檐角箭头升级。抵达中转城后需要再次派兵，不能自动越城。首关第一次成功派兵前战场冻结；教学首胜解锁策略资格，不直接赠卡。

新局采用外环与中央通道：可沿外侧扩张，或控制中央调兵。普通正式图单段行军约 2.9 至 5.6 秒，骑兵／兼行更快；电脑 8 秒起分批行动，各间隔 3.5 秒。一级步／弓／骑／塔营自然生产分别为 0.9／0.6／0.6／0.3 兵／秒。现有合法 v1.5 未完成对局仍按原节奏、直达规则继续，界面标明旧版；结束后的新局自动用 v1.6，已有成长保留。

本地记录按浏览器和站点地址隔离，请固定使用上述地址；`localhost` 与 `127.0.0.1` 不共享进度。刷新或切到后台后不会补算离线战斗，恢复需点击继续。关闭开发服务后无法首次加载页面；此版本没有离线安装或跨设备云存档。

首页按出征前庭稿布局：顶部小标题、军衔徽与设置，中部城关／军士，下部居中朱漆主动作，底部横排练兵、策略、周榜；主动作旁的小地图进入战前情报。完成首课且没有待处理结果、奖励或旧局时，“出征”直接开始正式局；“战前情报”可按需查看地图、军功规则和兵法。

独立“策略图鉴”按主动／被动分两排，点卡在原页面打开木绢说明，关闭恢复原位置；未解锁也可查询。正常造型中的军士和营地复用战场素材，灰态采用可区分的灰色军令轮廓。选策候选并排显示，选中后展示领取前后效果，底部确认固定可用，本次仍只领取一张。结算突出真实军功和奖励，“领取奖励／再来一局”为主动作，回首页和战报为次入口，短动效不锁点击。

暂停以原尺寸冻结战场为背景，居中弹层提供“继续对战”；回首页／设置／放弃使用小图标，被动和逐队军情通过“查看军情”展开。暂停页内查询时战场冻结，明确继续后才推进；战场直接点城查询仍实时推进。内页统一暖灰绢底、薄铜圆形图标、朱砂主按钮和按下反馈，策略采用同源军士与营地组成的军令卡；设置采用开关行，军功和玩法详则按需展开。

领取被动后，首页显示新层数和增益，扩营另显示一级容量；减少动态直接显示最终状态。战场背景延伸到顶部，暂停与时间采用小型铜木控件及绢面状态牌，保持安全区避让。点城显示 160×64px 短签，仅两行当前产兵速度与容量；升级门槛与消耗在玩法介绍中说明。可升级己城保留檐角箭头，短签避让箭头触区；保存成功才切换建筑。策略取消拖卡，改为点卡后点合法目标；兼行点选后随下一次合法派兵生效，真正派兵才消费。无效目标、取消、后台和旧回调不扣卡。出兵细路线与单个方向标记仅在拖动后显示，底部保留真实派／留、旅时和塔射提示。

有待处理对局或存档故障时，另开练兵使用临时无奖励会话。暂停页“退出临时练兵”只结束该次练习，之后可继续原已保存对局；没有可读资料时返回记录处理页，原损坏记录仍保留。

```sh
npm run check       # 类型检查、全部自动测试、两平台构建
npm run benchmark   # 连续 20 局 Node 规则计算基准，不是手机帧率
npm run visual      # 4174 端口固定页面测试数据，不保存、不计奖
npm run runtime     # 4176 端口正式平台生命周期检查，专用测试存档
```

微信独立策略验收可运行 `node scripts/wechat-audit.mjs cards` 或 `node scripts/wechat-audit.mjs reward`，再在开发者工具导入 `.tmp/first-version/wechat-audit`。前者载入有卡测试局并延后电脑行动，后者生成含屯田候选的受控冠军待领奖记录；`reward-logistics`、`reward-fortification` 分别生成含神速、扩营的候选。两者复用正式微信入口，屏幕固定标明“独立测试”，不作为玩家通关或平衡证据。默认每次生成独立记录编号；第三参数传回输出的编号可恢复同一测试记录，切换场景应使用新编号。同编号已有记录不会被重置，损坏记录仍进入恢复页。所有测试读写带独立前缀，不碰正式玩家槽；正常 `npm run build` 不包含该入口，测试包仅用于本机调试。

布局测试地址示例：[冠军选策](http://127.0.0.1:4174/?screen=choice) 。可替换为 `result`、`pause`、`battle`、`settings` 等页面；这些是布局样本，不代表实际获胜或真实存档，提交和返回可能因样本校验失败进入恢复页，不用于事务验收。具体验证记录见开发计划，自动测试通过不等于全部 290 项验收已签署。

[补兵反馈样本](http://127.0.0.1:4174/?screen=battle&scene=supply) 使用规则事件并固定在反馈开始后 80 游戏毫秒；`scene` 还支持 `reinforce`、`capture`、`mobilize`、`feint`。追加 `&motion=reduced` 可对照减少动态表现；样本均不保存、不计奖。

`scene=dispatch` 显示实际出发后的队列、方向与尘尾，出征回执持续 450 游戏 ms，真实队伍立即移动。可用 `&at=300`／`450` 对照可见与结束时刻。

`scene=march` 显示兼行后的真实行军；短尾线跟随方向，减少动态和拥挤时省略装饰，真实队首与数量保留。

`scene=clash` 显示真实敌军到达后的交战冲击，持续 550 游戏 ms；成功夺城仍保留交战接触，180 ms 后展开地面印记，整个序列持续 800 游戏 ms。`scene=capture` 可查看夺城场景。数字直接反映结算，不等动画结束。`scene=retreat` 仍是 160 游戏 ms 的残影清除，已淘汰队伍不再参与规则。

`scene=tower-pose`／`volley-pose` 使用真实塔射／齐射事件，箭矢反馈持续 300 游戏 ms。减少动态保留静态方向和真实扣数。`scene=persistent-status` 为明确标注的 v1.5 历史直达 256 队压力数据；当前路网压力由专项规则测试覆盖。

[灰度识别对照](http://127.0.0.1:4174/?scene=identity&grayscale=true) 展示正式绘制代码的阵营旗形、十二种营地轮廓和四兵种；任意布局样本也可追加 `&grayscale=true` 检查去色后的可读性。

布局样本可用 `?screen=ranks&scene=record-boundary`、`screen=library` 或 `screen=choice` 检查存储整数边界的长文本、精确容量及候选提示。该预设仅绘制、不保存，不用于模拟真实领取事务。

[内存交互验收](http://127.0.0.1:4174/acceptance) 使用同一规则、页面和存档事务，提供教学／有卡测试局、手动推进游戏时钟及写入故障按钮。它只读写该页面的内存，刷新即失去测试记录；不接触本地试玩进度。该入口用于开发验证，不计入真实玩家通关或平衡样本。

[道路战术试玩](http://127.0.0.1:4174/acceptance?scenario=tactical&width=375) 可载入有卡正式局，再开启正常时钟；支持 `map=A01`／`A02`／`A03`。这是内存测试场，便于检查留兵、外环绕行、停产后攻城及旧新节奏区别，不写入玩家进度。

[320 宽度选策交互](http://127.0.0.1:4174/acceptance?width=320) 点击“载入选策事务测试”，从受控截止状态经正式结算生成待选记录，可验证滑动、改选、稍后、放弃、领取及重新读取内存存档。`width` 还支持 375／430；加载预设只重置该页测试数据，不修改玩家存档。

容量和征兵边界可分别使用 `?width=375&scenario=capacity` 与 `?width=320&scenario=mobilize`，点击“载入有卡正式测试”载入 48／50 兵或三级步营预设；用“推进 1 游戏秒”观察额度耗尽与到期。这些初始状态仅用于测试，生产规则和地图参数不变。

火袭与查询可使用 `?width=320&scenario=feint`，点击“载入有卡正式测试”将既有 N5 塔营设为敌方、N2 弓营设为己方，两营各 20 兵。用于对照停产／停射、续时、出征及齐射查询；营地类型、位置和生产规则保持不变。

`scenario=coexist` 将敌塔设为 4 兵并带有征兵效果，用于火袭共存和夺城后的状态清除检查。“载入结算响应测试”保存一个距截止仅 1 ms 的受控战场，再用步进按钮触发正式结算；`scenario=result-loss` 可改为输局，其余为胜局。侧栏计时从正式会话发出已提交的结果事件开始，记录结果按钮可用及随后一帧回调的耗时；可配合写入故障按钮检查恢复路径。这些测量使用内存存储，不代表手机或微信存储性能。

`scenario=volley-clash` 为同刻齐射预设：两侧弓营距中心敌塔相同，金方已派 10 弓兵，玩家可从左弓营派出另一队。用“推进 100 游戏毫秒”分别观察准备、齐射清零和到达抵消；追加 `&motion=reduced&sound=off` 对照减少动态／静音设置下的画面。敌方预置派兵调用同一规则，不改变标准电脑，也不写入玩家进度；验收入口本身不播放声音。

齐射预设追加 `&target=friend` 可将中心塔改为己方，用于检查友援跳过齐射，以及查询中的“已跳过”状态；侧栏营地归属显示实际预设。

`scenario=reinforce` 将左弓营设为己方 20 兵、中心己塔设为 48／50 兵；从左营派兵到中心后点击“推进到最近到达”，检查实际归队与容量溢出。追加 `&capacity=full` 从满仓开始，用于确认没有虚增加兵或整编小人；仍只读写验收页内存。

`scenario=eliminate` 将中心塔设为赤方最后一城，并预派 10 守备兵沿中央至下方步营道路前进；玩家从左弓营攻下塔后，可检查败方在途队即时撤离及新占营地立即可用。敌方初始派兵通过正式规则生成，测试预设不改标准地图和电脑。

`scenario=capacity&start=42` 用于同游戏时刻两次乡勇的 42→48→50 检查；“重放最近施策反馈”只把同一事件交回绘制层，不重复规则或消费。“下次写入后读回不可用”模拟写入结果暂无法确认，需先“恢复存储读取”再重新读取内存存档；预设加载会重置该页故障。`scenario=card-result` 点击“载入结算响应测试”后有 3 张乡勇，可在截止前 1 ms 施策，再推进检查未结束的反馈与正式结算。

`scenario=crossing` 预派赤方右下到左上的步兵，玩家从左下拖到右上，形成交叉行军；中心金方塔按正常节拍攻击路过敌队。为隔离这次检查，预设将下一次电脑决策放在第 10 秒。“推进到最近到达”经正式时钟步进至当前最近的军团到达时刻，不直接调用到达处理或改兵数。

“重新读取内存存档”保留当前会话与画面实例，走正式重新读取流程；“损坏最新内存槽并读取”只破坏该验收页最新测试副本，用于验证恢复确认、同局回退与旧反馈清理，不接触本地试玩记录。

“重新创建会话并读取”从相同内存存档创建新的会话与画面实例，不等于杀进程或系统后台。`scenario=attack-restoration` 使用左侧己方弓营与中心敌塔，可在出兵后的 400 ms、塔射前的 1900 ms 暂停并重建；侧栏显示实际位置、齐射检查时刻和下一次塔射时刻，检查继续后是否沿原节拍处理。电脑决策从第 10 秒开始，标准地图和射击规则不变。

`scenario=dispatch-growth` 使用 21 兵起点；实际按住拖拽时，测试入口在首次移动推进 1 游戏秒、松手前推进 2 游戏秒，侧栏记录正式 Canvas 绘制的派留文字。用于检查 21→22→24 的预览与松手权威出兵，不能当作触屏延迟测量；其他预设仍仅由按钮推进时钟。

`scenario=army-list` 载入四方各 64 队的独立内存预设。追加 `&motion=reduced&sound=off&grayscale=true` 可检查减少动态和灰度可读性；灰度只作用于测试画布，验收入口本身不输出声音。从暂停页打开“沿路行军”可逐队分页查看精确人数、路线、到达时间与齐射状态，点队伍查看目标详情；军情和目标详情均保持暂停，明确继续后才恢复战斗。

`scenario=deadline` 从 209900 ms 开始，推进 100 游戏毫秒可检查最后 30 秒提示；`scenario=last-camp` 初始两座己营与两路敌军，1000 ms 后普通丢城并触发末城受袭。两者只用内存测试数据，提醒计数仅观察回调，不输出实际震动。

`scenario=query` 使用 A03 的四类己营和三种各 2 层的被动，一级营 30 兵、二级营 70 兵。用于逐页比较基础／有效属性、转换说明、升级前后容量与实际扣兵；通过正式暂停／恢复保存测试状态，仍仅使用该页内存。

追加 `&layers=100` 可检查三种各 100 层被动的实际战场与保存；“重放已提交战斗反馈”只将已有事件交给绘制层，并报告资料与存储是否保持不变。4174 交互验收和 4176 平台验收均固定显示测试标识；测试档内的奖励计数仅用于事务检查，不计入玩家军功或周榜。

`scenario=card-identity` 点击“载入有卡正式测试”进入七策战前预设，四主动各 3 张、被动各 4／5／6 层；可检查清单滚动、详情返回和四短标。`scenario=passive-reward` 点击“载入选策事务测试”，从已有 3 层屯田的测试档生成真实结算候选，用于检查 3→4 领取、重新读取和下一局快照；追加 `&reward=logistics` 或 `&reward=fortification` 分别检查神速、扩营，`&motion=reduced` 检查减少动态。侧栏记录已提交会话通知。两者仅使用当前验收页内存。

`scenario=week` 的有卡正式预设从周日 23:59:59 开始，提供“测试时钟推进至下周一”。战内经正式时钟检查触发跨周，其他页面经读档触发；可检查旧库存到期、局内兵法保留、首页摘要关闭及重建会话。它只推进验收页注入的现实时间，不修改系统时间或试玩存档；选策／结算预设沿用该页当前测试时间。

验收页还支持 `width=280` 的 280×508 紧凑窗口，以及 `safeTop=44`／`60`、`safeBottom=28`／`34` 的注入安全区。可用 `width=320&scenario=week&safeTop=60&safeBottom=28` 检查首页拖动与摘要关闭；这些尺寸只验证绘制边界，不等于真实手机或微信胶囊验证。

[浏览器渲染基准](http://127.0.0.1:4174/benchmark) 提供连续 20 局与 256 队拥挤场景检查，报告绘制耗时、帧间隔及特效／声音资源释放。自动操作和游戏时钟均加速，音频节点静音输出；仅使用内存测试数据，结果不能代表正常速度手机帧率或真实玩家平衡体验。

同页“检查音效并发（静音输出）”使用真实 AudioContext、振荡器和音量节点，检查同类合并、四路上限、优先级替换、静音、原生播放结束、暂停及恢复去重。最终输出经过测试专用静音总线；报告中的暂停为直接调用音频接口，不代表系统后台事件、手机震动或实际听音。

[正式平台生命周期验收](http://127.0.0.1:4176/) 通过 `npm run runtime` 启动，编译原始浏览器入口并附加测试观察器，保留正常时钟、平台事件处理和真实 Web Audio。存储使用 `runtime-audit:v1:` 专用前缀，不读取或覆盖该端口的旧试玩记录。“载入有卡测试局”只替换此专用测试档；“离开测试页”触发浏览器实际导航，返回后可核对可信 pagehide／visibilitychange、军团位置、效果期限、声音及完整战场。报告还显示表现设置、静音调用次数和调用后的活动声音数；调用次数包含空事件批次，不代表音效次数。该入口不是发布包；测试局为受控配置，不代表真实玩家成绩，桌面离页也不代表手机锁屏／来电验收。

同页可勾选“拖拽未松手时离页”：下一次真实按住拖动时导航到离开页，报告保留触发时的按键状态、待施策和拖拽起点，以及正式离页处理清理输入前后的状态。用于检查恢复后暂停等待继续、未松手不派兵／扣卡；该受控中断不等同系统切后台或杀进程。

“记录自然帧跟手”观察真实指针事件到下一次正常 Canvas 绘制完成的耗时，并记录路线末端、派留文字和松手后军团。它不主动绘制、不加速时钟；报告反映浏览器软件链路，不代表触屏与显示器的硬件延迟。取消或重新勾选会清空本次计时样本，不修改对局。

多城压力入口为 `/benchmark?width=320`（也支持 375／430）。点击“载入多城 256 队状态”检查四方各 64 队和 9 城征兵／停产状态；“推进多城压力至到达”绘制 300 帧并核对全部到达。源兵仅在测试准备时补足，运行沿用正式规则，不写入玩家进度。

同页“载入混合交战 256 队”包括弓兵齐射、兼行、异营友援、正常塔射，以及在途期间的两次升级和 40 次施策；“推进混合压力至结束”绘制 300 帧，对照完整终态和事件顺序，允许队伍被规则合法消灭。追加 `&motion=reduced&grayscale=true` 对照静态提示和灰度。报告记录原始战场、事件、绘制耗时和声音峰值，使用静音测试总线；这是受控组合，不是标准电脑或真实玩家样本。

[独立浏览器配额验收](http://127.0.0.1:4177/) 由 `node scripts/quota.mjs` 启动。点击检查后，只对该地址本次创建的测试键做有界填充，验证真实配额错误下旧档保留、完整 256 队存档重试及读回；结束清理本次测试键。该入口与试玩及其他验收地址隔离，不代表手机或微信配额；检查时请保留页面直到显示结果。

## 当前规则

拖出一半兵，抢城并守住最后一城；正式局最多四分钟，到时城多者胜，同城数比驻军与有效在途总兵力。

- 步兵营、弓营、骑营、塔营分别生产本营兵种；友援到达或成功占领后，存活者按目标营地 1∶1 转换。路过不转换，塔营不是弓营。
- 弓兵移速与步兵相同，出发至少 0.5 秒且进入目的地 70 范围后最多齐射一次，伤害为当时人数的 30%向下取整；不停步，驻营不自动射击，清零不等于占领。
- 营地按本营驻军门槛消耗部分兵力手动升级，最高三级；出兵不降级，易主保留等级。
- 塔营自动攻击真实射程内的敌方行军部队及敌营驻军，不限目标是否来袭本塔；清零不等于占领。
- 三关练兵、三张正式图，保留六图 42 个节点 ID；四类营地为首发设计，攻城营仅后续储备。
- 首发四主动、三被动。有效独立冠军从已解锁混合候选只选一张；主动使用扣一张、单局不限次数，被动按获得张数累计、每局自动，无胜场里程碑或总层数上限。
- 被动属性采用递减收益测试曲线；教学首胜永久解锁候选资格，不直接赠卡。
- 军功冠军 +30，第 2／3／4 名扣 5／8／10，最低 0；每 30 分一小级，可降衔、最高保留，不加战斗属性。
- 北京时间周一清当周库存、被动层数、待选和周冠军数；军功、最高、教学与永久卡池解锁保留。

## 技术和交付边界

本地核心与单局恢复；微信官方好友周榜为唯一业务数据联网例外，只比较同规则的当周对电脑冠军次数。不做真人服务、自建后端、账号、第三方统计、付费广告或完整云存档。12 种策略储备未启用。

技术路线为 TypeScript＋Canvas 2D，浏览器与微信小游戏共用规则与绘制代码，平台接口独立。无运行时第三方依赖；TypeScript 与 esbuild 仅用于检查和打包。浏览器需支持 ES2022、BigInt、Canvas 2D 和本地存储。声音使用 Web Audio，微信通过可选 `wx.createWebAudioContext` 接入；两端均支持静音、后台停声和恢复去重，微信实际听音仍待设备验证。

当前页面采用已选出征前庭风格：青灰城关首页、暖灰土石与三种地表、十二款分级手绘营地与 Canvas 回退、薄铜控件与朱漆主动作。军功突出当前值及晋升进度，升级采用檐角箭头，规则在玩法介绍中说明，策略说明与结算战报按需展开；详细数值与失败保护保留。

正式素材随包复制，不依赖图像服务或临时文件；缺失时先显示简图，设置页可查看载入状态并重试。来源与图集说明见 [素材说明](assets/art/README.md) 。浏览器保留 source maps 便于调试；微信代码压缩且不携带 source maps。构建按当前资源清单同步输出，清理产物中的旧图片，并逐文件检查微信目录总量不超过 4 MiB，超限直接失败。原始素材和根目录账号配置不参与清理；包体检查通过不等于正式发布验收。

`npm run build` 生成 `dist/browser/` 和 `dist/wechat/`。浏览器产物通过 HTTP 服务访问，不能直接双击 HTML。微信目录包含 ES2015 启动壳 `game.js`、ES2020 核心 `game-core.js`、`game.json` 与 `project.config.json`；启动壳对不支持 BigInt 的环境显示更新提示，不接触存档。构建不填假 AppID，不开启好友榜、托管成绩或好友资料请求。

微信本机开发：先执行 `npm run build`，再在开发者工具打开本项目根目录。根目录 `project.config.json` 保留当前配置的 AppID，以 `compileType: "game"` 和 `miniprogramRoot: "dist/wechat/"` 指向构建产物；重新构建不会覆盖根目录账号配置。若单独导入 `dist/wechat/`，需在工具中配置可用的小游戏 AppID。不要直接运行源码目录，也不要添加空 `app.json` 来掩盖导入模式错误。此前版本已实测小游戏首屏、手动开始练兵、重编译恢复，以及 7／7 资源载入、卡册与详情返回；方案 A 初版曾通过两端构建、本地页面／交互检查以及开发者工具自动预览（当时约 1.94 MiB）；新版已在 Stable 2.02.2608060 实际检查练兵拖拽、暂停继续、二／三级升级与重编译恢复；正式对局、四主动施策及三被动领奖已补微信模拟器实操，详细边界见开发计划；真机生命周期和感官体验仍待验证。

此前与当前开发者工具实查中，基础库 3.17.2／3.17.3 出现一条 `jsbridge not ready` 启动日志；不含游戏代码、存储或系统信息调用的最小 Canvas 项目也复现同一报错。它未阻止本次首屏和恢复检查，不能把控制台描述为完全无错误，详细对照见开发计划。

已知限制：尚未做手机真机安全区、微信存储配额／音频／更新验证；好友榜目前显示未启用状态。基础页面有 320／375／430 宽度检查记录，部分反馈仍待完整验收，不能代替不同设备验收；平衡和长期复玩体验仍需真实玩家试玩。当前不属于微信可发布版本。

项目约定见[AGENTS.md](AGENTS.md)。详细待办只维护在开发计划，不把文档更新当作原型／Figma／代码完成。

当前界面验证包含三尺寸摘要／详情／军衔折叠、稳定行军标签与真实塔射减员。`scene=army-hit&at=150` 可查看真实在途 20→19 与局部 −1；追加 `motion=reduced` 查看静态命中提示。最终验证与平台限制统一见[开发计划](docs/10-开发计划.md)。
